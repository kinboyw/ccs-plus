# Agent 退出后的终端恢复

ccsp 保留一个等待原生 agent 退出的父进程，不再以 `execvpe()` 替换自己。provider、工作目录、环境变量和原生 CLI 参数的生成方式不变。

## 恢复范围

- 启动前从实际 TTY 保存 POSIX 终端属性，退出时在 `finally` 中恢复，覆盖正常退出、非零退出和启动失败。
- 关闭常见鼠标上报协议、焦点上报、括号粘贴和同步刷新模式，退出备用屏幕并显示光标。`termios` 本身不保存这些终端模拟器模式，因此需要另外发送关闭序列。
- 控制序列通过单独打开的 TTY 描述符发送，不写入重定向的 stdout 或 stderr；没有 TTY 时不输出清理序列。
- 终端已断开或清理写入失败时尽力恢复，不用清理异常覆盖 agent 的退出结果。
- POSIX 信号退出码转换为 shell 通用的 `128 + signal`，普通退出码原样返回。

## 信号与作业控制

POSIX 下不新建 session 或进程组，不重新分配前台终端。agent 与 ccsp 继续位于 shell 分配的同一前台进程组，终端产生的 `Ctrl+C` 直接送达 agent；父进程不额外转发一次 `SIGINT`，也不会因 Python 的 `KeyboardInterrupt` 提前杀掉 agent。这让 agent 能保留自己的中断处理逻辑。

`Ctrl+Z` 和 `fg` 仍由 shell 的原生作业控制管理。父进程收到 `SIGTERM` 或 `SIGHUP` 时，如果 ccsp 是自身进程组的组长，会转发给整个进程组，包括仍在同组中的 agent 子进程；父进程临时忽略自身转发的信号以防递归。否则仅转发给直接子进程，避免误伤调用它的 shell 或其他任务。agent 主动脱离该进程组的后代不在组转发范围内。

Windows 保留子进程等待和 TTY 控制序列清理；POSIX `termios`、`SIGHUP` 与进程组转发不适用。

## 边界与手动恢复

agent 单独被 `SIGKILL` 终止后，仍存活的 ccsp 父进程可以清理终端；如果 ccsp 自身也被 `SIGKILL`，或者整个终端被关闭，无法保证清理。启动前保存的是 TTY 属性，而不是可查询并完整恢复的终端模拟器状态；退出时对交互模式采用关闭到 shell 常用状态的策略。

旧会话已经发生鼠标移动不断输入控制字符时，先按 `Ctrl+C` 清空当前命令，再执行：

```sh
printf '\033[?1000l\033[?1002l\033[?1003l\033[?1006l\033[?1015l'
```

若回显或换行也异常，再执行 `stty sane`。这些手动操作不修改 agent 或 provider 配置。
